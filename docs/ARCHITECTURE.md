# Architecture

Hindi Explainer Studio is a local-first production desk. It keeps operational workflow and channel editorial policy separate.

## System overview

```text
Browser UI (app/static/index.html)
        |
        v
Flask API (app/server.py)
        |
        +-- Projects / filesystem state
        +-- Background jobs / agent logs (app/agentlog.py)
        +-- Topic discovery and idea adaptation (app/topics.py)
        +-- Thumbnail ideas and drawing agent (app/thumbs.py)
        +-- Schedule / planner reader (app/planner.py)
        +-- Live YouTube state (app/ytstate.py, app/ytdata.py)
        +-- Analytics sync and analyst report (app/analytics.py)
        |
        +-- Claude Code CLI -> repo-local .claude/skills/*
        |
        +-- Configured rendering engine -> projects/<slug>/
        |
        +-- YouTube Data API / Analytics API (tools/yt_upload.py)
```

## Hosted AI workspace

The `web/` directory contains a separate Next.js application intended for Vercel deployment. It uses a server-side OpenAI Responses API route. Research requests require the built-in web-search tool; the API key is read only from server-side environment variables. A signed HTTP-only session cookie protects the single-owner app.

The cloud app currently exports a portable JSON handoff. It does not access local project folders or invoke local commands. The Flask app below remains the execution environment for Windows processes, the installed renderer, FFmpeg, local media and YouTube credentials. Do not expose the Flask server to the public internet. A future local companion should make outbound authenticated requests to a cloud queue rather than opening an inbound port on the PC.

## Adapted from Bean Studio

The following infrastructure was carried over from `PratyushK7/bean-studio` and rebased to this repository:

- Flask localhost dashboard and its tab structure.
- Project CRUD, upload sheet editing, background job management, log polling and file-derived progress.
- Atomic JSON store and cached Excel planner reader.
- Topic discovery based on public YouTube channel data and per-channel median outlier scoring.
- Thumbnail ideation and render orchestration.
- YouTube upload, schedule, live status and analytics integration.
- Defensive workarounds: localhost Host/Origin checks, duplicate-job protection, per-project upload lock, bounded logs and atomic JSON updates.

## Replaced editorial layer

The new repo-local skills define:
- Hindi-first research and claim verification.
- Natural spoken Hindi scripting.
- Documentary narrative structure.
- Hybrid visual grammar: code-generated motion graphics plus sourced documentary visuals.
- Hindi voice recording/TTS checks and subtitle QA.
- Serious thumbnails and YouTube packaging.

The original mascot/bean identity and comedy-writing rules are not part of this channel.

## Data boundaries

- `config.json`: local settings and paths; ignored by Git.
- `data/analytics.json`, `data/runs.json`, `data/youtube-videos.json`: local runtime state; not committed.
- `data/picks.json`: editable, intentionally shareable researched topic picks.
- `data/planner.xlsx`: local planner generated by `tools/build_planner.py`; do not use it as the only source of truth for live YouTube state.
- `tools/.secrets/`: OAuth client and token; never commit.
- `projects/`: local video project files. Generated media and upload logs are excluded from Git.

## Renderer boundary

Bean Studio itself did not contain the complete animation renderer or animation kit. It invoked a locally installed `line-boil` engine from the Claude animation skills kit. This repo keeps that renderer as a configurable dependency; see [engine/README.md](../engine/README.md).

The Hindi skills are deliberately renderer-aware rather than claiming a new Hindi renderer already exists. Hindi font shaping, TTS and word alignment must be validated against the installed engine before a long render.

## Security model and limitations

- The Flask server binds to `127.0.0.1` and rejects unexpected Host/Origin requests.
- This is a personal local tool, not a production multi-user service.
- The process runner is Windows-oriented (`CREATE_NEW_CONSOLE`, `taskkill`, `os.startfile`); Windows is the supported baseline for this adaptation.
- Background jobs are in-memory. Restarting the Flask process loses live job state, but not the produced files.
- YouTube API data has availability and freshness limits. The UI must continue to label proxy metrics and delayed data accurately.
